## Freeze rules and independent authority

1. Current **weekly CN / Master Monday** remains the sole originator of week-ahead and 2–8-week strategic forecasts. Existing weekly freeze/score materializer is authoritative for Price Range. Official Compass is the tactical/action and Protection Tracker owner; it may append prospective short-term WARN/NONE/UNKNOWN declarations after its own independent time-stamped publish. The new repo is a **read-only auditable mirror and evaluator**, not an official direction, notification or execution owner.
2. Only source evidence frozen with an exact SHA-256 of original bytes, public CN issue, ISO week, UTC `issued_at`, start/end UTC and scoring-method version is eligible. Each claim is a separately versioned immutable issue. `issued_at < evaluation_window.start` (strict). A later public release timestamp cannot falsely replace missing earlier proof.
3. W42 starts Monday, **2026-10-12**. If existing weekly CN pipeline publishes after Monday 00:00 UTC, first scored interval must start at the existing `FIRST_COMPLETE_UTC_HOUR_AT_OR_AFTER_FREEZE_v1` or later. Do not claim 168/168 advance coverage if the forecast did not exist before every hour. Long-running forecasts are scored only from their own first eligible hour. The site must show this limitation.
4. A 2–3-week claim published W42 remains attached to its W42 source until maturity. W43 and W44 publish their **own new claims alongside it**, never update the W42 claim. Distinct 14d/21d/28d/56d checkpoints can be frozen for the same underlying thesis, but overlap does not create independent evidence or 4× edge.
5. Any Compass tactical refresh is a new source event with new `compass_id`, source digest and valid-from UTC. Do not rewrite the earlier weekly claim. Distinguish `NO_WARNING` (valid prospective assertion) from `UNKNOWN` (abstained) and `UNAVAILABLE` (input absent). An absence of a warning only counts if the owner explicitly declared NONE/NORMAL in the frozen projection; missing data never grants a true negative.
6. Exact scoring method and thresholds must be frozen **before** any W42 outcome inspection. Subsequent research may create a separate v2.1 prospective method; it may not silently recompute the v2 public track record.
7. Revisions/corrections append separate immutable releases. Never change prior freeze, thresholds, window, or earlier recorded score.

## Typed binary claim grammar

Each scorable claim requires `claim_id`, `family`, `kind`, `issued_at_utc`, `scoring_start_utc`, `evaluation_end_utc`, `source_sha256`, `public_issue_number`, `forecast_week`, `statement_da`, `statement_en`, `evidence_spec`, `predicate`, `scope_id`, `origin` and `scoring_contract`.

### DIRECTION_ROTATION_CLAIMS
- `kind=METRIC_COMPARISON`: structured `metric` and `operator` `LT|LTE|GT|GTE|EQ` and numeric threshold. Example: `ETHBTC_WEEKLY_CLOSE <= ETHBTC_WEEKLY_OPEN`. No text parsing or scoring generated by guessing from qualitative descriptions.
- `kind=DIRECTIONAL_CLOSE`: `metric` with a pre-frozen anchor and nonzero tolerance (e.g. +1% vs frozen reference), `expected=UP|DOWN|SIDEWAYS`. Exactly which close and which source must be declared. 'MIXED' by itself is **not a cheap 100**; it needs a measurable signed-band predicate registered ex-ante.
- Flow calls require settled-source sign, exact units, source, settlement dates/coverage; missing ETF/spot feeds => null, not false. Rotation requires explicit official breadth thresholds and cross-tier metrics; if no official tier source, record `ABSTAIN` for that component.

### PULLBACK_EDGE
Freeze separate claims:
- `EVENT_OCCURRENCE`: `expected_event=true|false` and a fixed severity band/threshold in the published time window. Example: `NO_WARNING` with `expected_event=false` for a **material BTC pullback >=5%**; only eligible when Official Compass *explicitly* says NORMAL/NONE and the chosen 5% event definition is frozen.
- `START_WINDOW`: bracket `earliest_utc/latest_utc` when genuinely source-supported. Grade 100 if a qualifying **first threshold crossing** occurs in it, 0 if confirmed outside it, null if no independently resolved event or no bracket. Show a separate lead-time field warning_utc < onset_utc.
- `END_WINDOW`: bracket on confirmed recovery time; grade only if event resolves and source provided a bounded end forecast. Otherwise RIGHT_CENSORED/null.
- `SEVERITY_CLASS`: predicted `SMALL|MATERIAL|MAJOR` and a pre-registered threshold classifier using BTC peak-to-trough drawdown for the exact horizon.
- `ALTCOIN_IMPACT`: `LOW|MEDIUM|HIGH` using a *predefined, available* broad-market altcoin basket return/drawdown versus BTC during the same event, with constituent list, exchange source and coverage frozen. **If no reproducible tier basket exists this claim must be ABSTAIN/NULL**, never assume microcap impact from BTC.
- `NO_WARNING` is a positive measurable assertion: if a qualifying pullback occurs within its horizon it earns 0 (miss), otherwise 100. An explicit warning that fails to materialize earns 0 (false alarm); correct detection earns 100 (hit). Keep timing/severity/alt impact separate and not automatically 0 when not predicted.

### Event definition v2.0 — proposed experimental, pre-registration required
- Asset: independently observed BTC/USD hourly OHLC with 100% eligible coverage and clearly defined session UTC.
- Drawdown = 100 × (running observed peak-high − subsequent trough-low) / running peak-high. Only peaks/troughs inside event horizon after valid freeze. No use of a previous unknown peak.
- SMALL: 3% <= drawdown < 5%. MATERIAL: 5% <= drawdown < 10%. MAJOR: drawdown >= 10%. A 7-day event call is a >=5% **material** threshold unless a different fixed threshold was explicitly supplied before freeze.
- First `start/onset` for score timing = first hourly *low* that crosses the pre-specified drawdown threshold. Report `peak_time` separately; don't pretend a warning preceded the peak when it only preceded threshold-cross.
- `trough_time` = first timestamp of maximal realized drawdown inside the evaluation window. `end/recovery` = first eligible hour after trough whose *high* reclaims >=50% of price loss (trough -> preceding peak), if achieved before the evaluation-window close. If not recovered by maturity, `end=RIGHT_CENSORED` (not a fabricated date). Open-hour bars with ambiguous high/low sequencing cannot be used to claim an intrahour detection edge.
- The above thresholds and recovery rule are **proposed v2.0 instrumentation**, not proven optimal trading triggers. The definition itself must be reviewed/frozen before being used to score any new claim.
- Pullback impact on altcoins: start with an **INDEPENDENT_DATA_PENDING** state. Only introduce a basket when you can prospectively fix constituents, micro/large buckets and source coverage; don't make unsupported claims while waiting.

## Scoring, anti-gaming and Edge statistics

Each evaluation has `result=SUPPORTED|REFUTED|PENDING|NOT_EVALUABLE|ABSTAIN|RIGHT_CENSORED`; `score=100|0|null` with UTC evidence, source path, proof hashes and reason. There is **never a 50 for 'mixed'**, and missing data is never a 0.

Display coverage as **(supported + refuted) / all eligible declared and matured claims**, plus pending and abstentions separately. Report hit-rate, false-alarm-rate, miss-rate, true-negative-rate and median warning lead time with exact denominators. Show **always-NO_WARNING** and **always-WAIT** baseline comparisons over the identical windows. Compute block-bootstrap confidence bounds over independent weekly/event families, not overlapping intraday outcomes treated as independent. Don't call a score statistically superior or a reliable investment Edge without a sufficiently large prospective, independently confirmed sample and realistic slippage/transaction/portfolio-utility review.

No one forecast family gets hidden by averaging. Present an honest evidence table by week:
- Actual Price Range Weekly; Intraday D1–2/D3–4/D5–7;
- Weekly Flow/Rotation Claim accuracy [x/y] + coverage;
- Maturing 14d/21d/28d/56d forecasts from all original issue weeks;
- Pullback detection/timing/severity/alt impact subclaims + lead time, abstentions and misses;
- Immutable release status of exact freeze and scoring receipt.
